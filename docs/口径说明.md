# 口径说明

这份文档是网页与数据脚本共同的口径来源。改口径改这里 + `scripts/build_rows.py` 里的映射表。

## 六个维度

| 维度 | 字段 | 取值 | 怎么定的 |
|---|---|---|---|
| 一 | 一级维度（六大模块） | 人力资源规划 / 招聘与配置 / 培训与开发 / 绩效管理 / 薪酬福利 / 员工关系 / 待定位 | 沿用集团既有六职能口径（企业数据库六大职能面板），不另起一套 |
| 二 | 二级维度（人/流程/成本） | 人 / 流程 / 成本 / 其他 | 人＝具体的人、岗位、编制、招聘、培训、宣贯、盘点、访谈、员工信息；流程＝制度、标准、审批、机制、系统配置、发布与库维护；成本＝钱（测算、费用、补贴、薪酬标准、预算） |
| 三 | 具体事项 | 事项名 | 沿用源表「分项」列（源表里那一列装的就是事项名） |
| 四 | 分项 | 子项名 | **源文本点名才拆**：销售提点→茅森/恐龙/聚力提点；研创院工程考核→两个考核方案；职位职级与后台月薪标准→三类机构核查。其余分项＝事项名 |
| 五 | 分项内容简介 | 一句话 | 沿用源表「概要」；制度类 3 条改为写 4 制度 6 细则的逐项归口 |
| 六 | 最新进展 | 进展日期 + 进展内容 | 拆源表「最新进展」列：每行一个日期一条进展 |
| 七 | 周计划 | 当日计划（周计划） | 拆源表「周计划」列，**按天逐行**；同一天的计划只出现一次，优先挂在当天第一条进展行上 |

## 行的粒度

一行 = 事项 × 分项 × 日期。

- 有进展的（分项，日期）→ 一行，带当天进展内容
- 只有计划、没有进展的（事项，日期）→ 一行，分项取主分项，进展内容留空
- 区间型计划（如 `1019-1030每日跟进`）按日展开

**「最新进展」怎么读**：按「事项序号↑ / 进展日期↓」排序后，每个事项块第一条非空进展就是该事项的最新进展。

## 源表里的两个数据问题（网页如实呈现，未擅自改数）

1. **事项序号有重复**：源表第 13 号出现两次（办公配置标准住宿标准梳理 / 武进人力成本比较分析），第 20 号出现两次（候选人分析前置 / 核心人员离职评估报告定稿及发布）。源表今天新增的两行没填序号，抽取时按顺序补了位，因此出现重复。**要在源表里把序号排成连续且唯一**。
2. **第 17 行起是从别处粘贴进来的行**，事项名落在 C 列而不是 D 列（整行左移一列）。抽取器已按「D 非空取 D；否则 C 非空且 E 非空取 C」处理，网页里看到的分组是正确的。

## 数据清洗规则

| 情形 | 处理 |
|---|---|
| 日期写成 `1118`（应为 1018） | 自动归一 |
| 日期写成 `2021/2023/2025`（应为 1021/1023/1025） | 自动归一 |
| 进展没有日期前缀 | 按该事项的开始时间落行，并标「待核」 |
| 进展与周计划都为空 | 按开始时间落一行空行，标「待补」 |
| 源表列错位（粘贴行，事项名落在 C 列） | 抽取时按「D 非空取 D；否则 C 非空且 E 非空取 C」处理 |
