# 集团人力重点工作进度表 · 网页版

把《集团人力近期重点工作进度表》重组成**六维度长表**的网页版：六大模块 → 人/流程/成本 → 具体事项 → 分项 → 分项简介 → 最新进展（日期＋当天进展）→ 开始/完成时间 → 周计划（逐日，与进展一一对应）→ 责任人/负责人类型/协调事项。

**零合并单元格**：一行 = 事项 × 分项 × 日期，进展与当日计划同行并列。

---

## 数据从哪来

唯一数据源是**企业微信在线表格**《集团人力近期重点工作进度表》：

```
企业微信在线表格 工作表1
   │  scripts/extract_online_sheet.py   ← 抽取（含今天重排造成的列错位修正）
   ▼
data/tasks_online.json                  ← 43 个事项的原始数据
   │  scripts/build_rows.py             ← 展开成长表（归属映射按「事项名」索引）
   ▼
data/rows_v2.json                       ← 167 行 × 15 列
   │  scripts/build_data_js.py          ← 打包给网页直接读
   ▼
data/rows.js                            ← window.HR_DATA
```

网页是**静态的**，只读 `data/rows.js`；数据更新靠跑一次 `scripts/refresh.sh`。

## 本地预览

```bash
cd hr-progress-table
python3 -m http.server 8000
# 浏览器打开 http://127.0.0.1:8000
```

直接双击 `index.html` 也能打开（数据以 JS 文件加载，不走 `fetch`，所以 `file://` 下可用）。

## 刷新数据

前置：本机已装 `wecom-cli` 并完成企业微信机器人授权。

```bash
./scripts/refresh.sh
```

脚本会依次：抽取在线表格 → 展开长表 → 重新生成 `data/rows.js`。
改归属口径只改 `scripts/build_rows.py` 里的映射表（按**事项名**索引，源表重排后仍对得上），然后重跑即可。

## 口径（当前版本）

| 维度 | 取值 | 说明 |
|---|---|---|
| 一级维度 | 人力资源规划 / 招聘与配置 / 培训与开发 / 绩效管理 / 薪酬福利 / 员工关系 / 待定位 | 沿用集团既有六职能口径；「待定位」= 制度清单未给全 |
| 二级维度 | 人 / 流程 / 成本 / 其他 | 人=具体的人与编制招聘培训；流程=制度标准审批机制系统配置；成本=钱 |
| 分项 | 源文本点名才拆，否则＝事项名 | 不制造源数据里没有的分项 |
| 进展日期 | 该行锚定的日期 | 一行 = 一个事项的一个分项在一个日期上的状态 |
| 当日计划 | 某天的安排 | 计划面向未来、进展是历史累积，二者在同一行对齐 |

**三项还没拍板**（网页里以「口径待定」标注，不臆造含义）：

1. **负责人类型 A/B** —— 原表全是 B 且没有图例，含义未知
2. **协调事项** —— 原表整列为空
3. **制度类 3 条的逐制度进展** —— 4 制度 6 细则的名单已定位（见 `scripts/build_rows.py` 的 `POLICY`），进展待补

另有 6 条**待核**记录（原文进展没有日期，按开始时间落行），网页里带「待核」徽标。

## 上线

见 [`docs/DEPLOY.md`](docs/DEPLOY.md)：四种方案——**GitHub Pages**（需公开仓或 GitHub Pro；内部数据不建议公开）、**自有云服务器 + nginx**（推荐）、**Docker**、**腾讯云 CloudBase 静态托管**。

> 仓库默认 `private`。内部 HR 进展与责任人数据不适合公开，因此实际推荐走 **B（自有服务器 + nginx）**：服务器上 `git pull` 后由 nginx 直接托管静态文件。
