# 集团人力重点工作进度表 · 网页版

把《集团人力近期重点工作进度表》重组成**六维度长表**的网页版，并加上**多用户、记一笔进展、新建任务、进度面板**四件事。

六大模块 → 人/流程/成本 → 具体事项 → 分项 → 分项简介 → 最新进展（日期＋当天进展）→ 开始/完成时间 → 周计划（逐日，与进展一一对应）→ 责任人/负责人类型/协调事项。

**零合并单元格**：一行 = 事项 × 分项 × 日期，进展与当日计划同行并列。

---

## 现在有什么

### 读（三种视图 + 面板 + 筛选）

- **事项视图**（43 行，一行一个事项）——点行展开，看分项与逐日记录：日期 | 进展内容 | 当日计划
- **明细视图**（167 行 × 15 列长表）——严格按六维度顺序排，零合并单元格
- **甘特视图**——按模块配色、今日线、月份与旬刻度
- **进度面板**（第 4 个 tab）——四张 KPI 卡 + 按模块 / 按责任人 / 逾期项 / 本周动态
- 筛选（模块·性质多选、责任人、关键词、本周）、四种排序、CSV 导出、打印、深色模式、移动端卡片

### 写（多用户）

- **身份胶囊**：页头右侧显示姓名、角色、可写事项数；无写权限的按钮**不渲染**
- **记一笔进展**：最高频动作，2 次交互；手机上是全屏抽屉，软键盘不会顶掉「保存」
- **新建任务**：整页表单，四级级联（模块→性质→事项→分项）
- **写进哪里**：直接**追加**到企业微信在线表格《集团人力近期重点工作进度表》的子表「重点工作进度 v2」——网页不是另一份真相源，别人在表格里改也能看到

## 跑起来

### 方式一：纯静态（双击就能开，零后端）

```bash
cd hr-progress-table
python3 -m http.server 8000     # 打开 http://127.0.0.1:8000
```

或直接双击 `index.html`（数据走 `<script src="data/rows.js">`，`file://` 下可用）。
此时是**只读模式**：写入口全部隐藏，面板改用本地快照算聚合。

### 方式二：带后端（多用户与写入需要）

```bash
python3 server.py                            # http://127.0.0.1:8787
HPS_SHEET_ADAPTER=file python3 server.py     # 只读本地快照（写接口返回 501）
HPS_SHEET_ADAPTER=mock python3 server.py     # 本地假表（开发用，不碰真表）
HPS_SECRET="$(openssl rand -hex 32)" python3 server.py   # 上线必须换密钥
```

| 环境变量 | 默认 | 说明 |
|---|---|---|
| `HPS_SECRET` | `dev-secret-change-me` | 会话签名密钥，**上线必须改**（用默认值启动会打警告） |
| `PORT` | `8787` | 监听端口 |
| `HPS_SHEET_ADAPTER` | `cli` | `cli`＝用本机 `wecom-cli` 读写企微在线表格；`file`＝只读本地快照；`mock`＝本地假表 |
| `HPS_WECOM_DOCID` | `e3_ARsADAagAHQCNea2Y2u1wSA00hrX0` | 源表 docid |
| `HPS_WECOM_SHEET_TITLE` | `重点工作进度 v2` | 源表子表名 |
| `HPS_BACKUP_WINDOW_DAYS` | `90` | 补录窗口（更早要 admin） |

**后端零第三方依赖**：只用 Python 标准库（`http.server` / `sqlite3` / `json` / `urllib` / `hmac` / `subprocess`）。

### 刷新数据

```bash
./scripts/refresh.sh
```

抽取在线表格 → 展开成长表 → 生成 `data/rows.js`。
改归属口径只改 `scripts/build_rows.py` 的映射表（按**事项名**索引，源表重排后仍对得上）。

### 跑测试 / 体检

```bash
HPS_SHEET_ADAPTER=mock python3 tests/test_api.py   # 53 个用例，全程不碰真表
python3 scripts/build_data_js.py --check            # 数据打包自检
python3 scripts/verify_data.py                      # 数据体检（43 事项 / 167 行 / 字段序 / 日期 / 取值域）
```

## 数据从哪来

```
企业微信在线表格《集团人力近期重点工作进度表》→ 子表「重点工作进度 v2」（15 列）
   │  scripts/extract_online_sheet.py   ← 抽取（含重排造成的列错位修正）
   ▼
data/tasks_online.json                  ← 43 个事项的原始数据
   │  scripts/build_rows.py             ← 展开成长表（归属映射按「事项名」索引）
   ▼
data/rows_v2.json                       ← 167 行 × 15 列
   │  scripts/build_data_js.py          ← 打包给网页直接读
   ▼
data/rows.js                            ← window.HR_DATA
```

写入方向是**反过来的**：网页的写操作由 `server.py` 追加回源表「重点工作进度 v2」的末尾，**只 append、不改已有行**（源表是多人共编的，改行会覆盖别人的手改）。

## 口径（当前版本）

| 维度 | 取值 | 说明 |
|---|---|---|
| 一级维度 | 人力资源规划 / 招聘与配置 / 培训与开发 / 绩效管理 / 薪酬福利 / 员工关系 / 待定位 | 沿用集团既有六职能口径；「待定位」= 制度清单未给全 |
| 二级维度 | 人 / 流程 / 成本 / 其他 | 人=具体的人与编制招聘培训；流程=制度标准审批机制系统配置；成本=钱 |
| 分项 | 源文本点名才拆，否则＝事项名 | 不制造源数据里没有的分项 |
| 进展日期 | 该行锚定的日期 | 一行 = 一个事项的一个分项在一个日期上的状态 |
| 当日计划 | 某天的安排 | 计划面向未来、进展是历史累积，二者在同一行对齐 |

**三项还没拍板**（网页里以「口径待定」标注，不臆造含义）：

1. **负责人类型 A/B** —— 原表全是 B 且没有图例，含义未知
2. **协调事项** —— 原表整列为空；新建任务表单里该字段**禁用**，不开放填写
3. **制度类 3 条的逐制度进展** —— 4 制度 6 细则的名单已定位（见 `scripts/build_rows.py` 的 `POLICY`），进展待补

另有 6 条**待核**记录（原文进展没有日期，按开始时间落行），网页里带「待核」徽标。

### 面板 KPI 的口径（实测值，2026-10-24）

| 指标 | 值 | 口径 |
|---|---|---|
| 逾期 | 7 项（最久 9 天） | 今天已过完成时间，且还没有一条进展日期 ≥ 完成时间的非空进展 |
| 到期完成 | **8 / 15** | 分母是**已到期**（完成时间 < 今天），不是 43。**故意不显示「完成率」**——那会把「还没到期」算成「没完成」 |
| 本周更新 | 20 条 / 15 事项 | 周一至周日 |
| 7 天无进展 | 12 项（最久 16 天 · 1 项从未） | 末次非空进展距今 ≥ 7 天 |

## 上线

见 [`docs/DEPLOY.md`](docs/DEPLOY.md)。带后端的部署（推荐）：**自有云服务器 + nginx 反代 + systemd 常驻**，10 分钟能上完。

> 仓库默认 `private`。内部 HR 进展与责任人数据不适合公开，GitHub Pages 免费版又只支持公开仓，所以实际推荐走自有服务器。
